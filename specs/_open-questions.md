# 待决问题与实现时需确认的细节

> Source: Deep Interview, 2026-08-15

## 需用户后续输入
- 语法填空序号缺失时,首个题号由用户在运行时提供(交互式输入或 `--first-q` 参数)。
- 词义猜测规则表初始条目需从 1-2 份真实试卷样本归纳(题干模式:underlined / 加粗等),之后按案例积累。
- 完形填回标记格式确认:`21. A.… D.… → A`(箭头+字母);与选项文字中出现的箭头/字母冲突的转义规则。

## 实现时需收集/验证
- 题型标题变体清单:完形填空 / 完形 / Cloze;七选五 / 阅读七选五;语法填空 / 语篇填空 / 短文填空;阅读理解 / Reading 等。
- OCR 答案前缀形态:"C21."、"AB 26."、"( ) A 29."、"31.A." 等正则覆盖,防止误剥正文字母。
- 完形正文手写答案与序号下划线的混排(underline 数字 vs underline 单词)判定顺序。
- 七选五选项表通常位于正文之前,标题驱动合并时选项表块归属。
- ocr.py 多 `layoutParsingResults` 的文件命名冲突行为(现状 `doc_{page_num}.md` 递增,需复核覆盖风险)。
- PaddleOCR-VL 对"全图片 PDF"的分页与竖版/横版识别表现(用现有「扫描全能王 2026-8-15 20.18.pdf」实测)。
- 阅读配图引用路径的相对性(md 与 imgs/ 的相对位置,便于打印与移动)。
- 填充脚本对"已填充"状态的可重入性(重复跑不重复填/不误删未标记行)。

## 范围外(本访谈明确排除)
- Anki 制卡、答案/解析/错因字段、听力/作文/读后续写板块。
- 自动印刷/手写下划线区分(依赖规则表渐进,不做模型级判断)。
- 完形以外的题型(阅读/七选五/语法填空)不做"填回"功能。
